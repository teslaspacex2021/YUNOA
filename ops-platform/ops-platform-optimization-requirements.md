# 知识运营管理平台优化需求文档

> 基于"诊断 AI 智能体"需求，针对现有知识运营管理平台的功能优化方案

---

## 一、背景与目标

### 1.1 现状分析

现有知识运营管理平台中，前端用户反馈的点踩问答统一在"我的待办"列表下展示。运营人员在处理这些点踩问答时，面临以下问题：

- 大量用户仅点踩、未提供具体原因，运营人员缺乏明确的处理方向
- 缺少自动化诊断能力，运营人员需要手动逐条分析点踩原因
- 问题分类不清晰，无法高效定位是知识库缺失、模型能力不足还是系统Bug
- 处理流程不够标准化，不同运营人员的处理质量参差不齐

### 1.2 优化目标

通过接入"诊断 AI 智能体"，实现：

1. **自动诊断**：对所有点踩问答（存量+增量）进行 AI 自动诊断并精准分类
2. **提效降本**：减少运营人员手动分析时间，提升处理效率
3. **标准化处理**：基于 AI 诊断建议引导运营人员标准化处理
4. **闭环追踪**：完整记录处理过程，支持效果评估

## 二、功能需求

### 2.1 接入"诊断 AI 智能体"

| 项目 | 说明 |
|------|------|
| 触发时机 | 每一条新增的点踩问答自动触发 AI 诊断 |
| 存量处理 | 对历史存量点踩待办进行批量 AI 诊断 |
| 诊断内容 | 分析点踩原因并归类（如知识库缺失、方案模板化、结果不准确、输出幻觉、上下文关联错误、能力有缺失、耗时长、内容渲染问题等） |
| 输出结果 | 诊断类型 + 分析步骤 + 修复建议 |

### 2.2 待办列表页优化

#### 2.2.1 新增字段

在现有待办列表中新增以下两列：

| 字段名 | 说明 | 展示规则 |
|--------|------|----------|
| 用户反馈 | 用户点踩时填写的反馈原因类型 | 有值则显示标签，无值显示"未反馈" |
| AI 诊断 | AI 智能体诊断出的点踩原因类型 | 有值则显示标签，诊断中则显示"诊断中..." |

#### 2.2.2 状态筛选

- 新增状态筛选下拉框，支持按"全部"、"待处理"、"已处理"过滤
- 配合关键字搜索实现组合查询

#### 2.2.3 批量操作

- **批量转派**：选中多条待办后，可一键批量转派给其他运营人员
- **批量删除**：选中多条待办后，可一键批量删除

#### 2.2.4 操作列规则

| 状态 | 处理 | 转派 | 删除 |
|------|------|------|------|
| 待处理 | 可点击，进入详情页 | 可点击，弹出转派弹框 | 可点击，确认后删除 |
| 已处理 | 置灰不可操作 | 置灰不可操作 | 置灰不可操作 |

### 2.3 待办详情页优化

#### 2.3.1 基本信息区

详情页顶部展示以下信息：

- **第一行**：反馈人、反馈时间、用户反馈（有值显示标签，无值显示"未反馈"）、来源智能体
- **第二行**：AI 诊断结果标签（可点击查看诊断详情）+ 修复建议（直接展示，附"去处理"按钮）

#### 2.3.2 AI 诊断详情侧边栏

点击 AI 诊断结果标签后，从右侧拉起侧边栏，展示：

| 区域 | 内容 |
|------|------|
| 头部 | 诊断类型、诊断时间 |
| 分析步骤 | 按序号展示 AI 诊断的分析过程（如：问题意图识别 → 知识库检索 → 回答质量评估 → 诊断结论） |
| 修复建议 | 具体建议列表，每条建议附"去处理"按钮 |

#### 2.3.3 "去处理"交互规则

根据 AI 诊断结果类型，点击"去处理"后的交互不同：

| 诊断结果/建议类型 | 点击"去处理"后的行为 |
|------------------|----------------------|
| 修改已有知识库内容 | 弹出"填写处理记录"弹框，填写后标记为已处理 |
| Bug 类型（如输出中断、上下文关联错误等） | 弹出"填写处理记录"弹框，填写后标记为已处理 |
| 新增知识（SQL 数据集/知识问答/业务术语） | 弹出"新增知识"弹框，直接录入新知识，保存后标记为已处理 |

#### 2.3.4 已处理状态规则

- 已处理待办的详情页 **不再显示"提交"按钮**
- 修复建议中的"去处理"按钮替换为"已处理"灰色标签
- **处理记录**区域展示完整的处理信息：处理状态、处理人、处理时间、处理说明

#### 2.3.5 内容展示区

- **回答内容**标签页：展示 AI 智能体的回答内容
- **相关问答记录**标签页：展示该用户的关联历史问答（预留）

#### 2.3.6 底部操作栏

| 按钮 | 说明 |
|------|------|
| 取消 | 返回待办列表 |
| 提交 | 仅"待处理"状态显示，提交本次处理结果 |
| 上一条/下一条 | 导航切换待办条目 |

## 三、AI 诊断分类体系

### 3.1 诊断类型定义

| 诊断类型 | 说明 | 典型场景 |
|----------|------|----------|
| 知识库缺失 | 知识库中缺少相关知识条目 | 用户问"如何预定会议"，知识库无此条目 |
| 方案模板化 | 回答内容过于模板化，缺乏针对性 | 回答仅列通用步骤，缺少截图和具体路径 |
| 结果不准确 | 回答内容与事实不符 | 知识库数据过期导致回答有误 |
| 输出幻觉 | 模型生成了看似合理但不真实的内容 | 回答引用了不存在的数据或政策 |
| 上下文关联错误 | 多轮对话中未能正确关联上下文 | 用户简短追问被当作独立问题处理 |
| 能力有缺失 | 知识库覆盖不足，缺少特定领域知识 | 缺少员工福利政策类知识 |
| 耗时长 | 回答生成时间过长 | 响应时间超过正常阈值 |
| 内容渲染问题 | 输出过程中出现中断或渲染异常 | 回答文本中断、重复输出 |

### 3.2 用户反馈类型

| 反馈类型 | 说明 |
|----------|------|
| 耗时长 | 用户反馈等待时间过长 |
| 结果不准确 | 用户认为回答与事实不符 |
| 方案模板化 | 用户认为回答过于泛化 |
| 答非所问 | 用户认为回答未解决实际问题 |
| 交互体验差 | 用户反馈界面或交互有问题 |
| 未反馈 | 用户仅点踩未填写具体原因 |

## 四、处理流程

```
用户点踩问答
    ↓
自动触发 AI 诊断
    ↓
生成诊断结果（类型 + 分析步骤 + 修复建议）
    ↓
运营人员在"我的待办"查看列表
    ↓
进入待办详情页
    ↓
查看 AI 诊断结果和修复建议
    ↓
点击"去处理"
    ├── 知识类 → 新增知识弹框 → 录入知识
    ├── Bug类 → 填写处理记录弹框 → 记录Bug工单
    └── 修改类 → 填写处理记录弹框 → 记录修改说明
    ↓
提交处理结果
    ↓
标记为"已处理"，记录处理人、处理时间、处理说明
```

## 五、数据埋点与效果指标

### 5.1 关键指标

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| AI 诊断准确率 | AI 诊断结果与运营人员实际判断的一致率 | 诊断正确数 / 总诊断数 |
| 平均处理时长 | 从待办创建到处理完成的平均时间 | 优化前后对比 |
| 运营人员处理效率 | 每人每日处理的待办数量 | 优化前后对比 |
| 用户反馈率 | 点踩时填写详细原因的用户占比 | 有反馈用户数 / 总点踩用户数 |

### 5.2 埋点需求

- 记录运营人员进入详情页时间、离开时间（计算停留时长）
- 记录"去处理"按钮点击次数和对应诊断类型
- 记录处理结果的提交时间
- 记录 AI 诊断耗时

## 六、非功能性需求

| 项目 | 要求 |
|------|------|
| AI 诊断延迟 | 新增待办后 ≤ 30 秒完成诊断 |
| 存量诊断吞吐 | 支持 ≥ 1000 条/小时 的批量诊断 |
| 页面加载性能 | 列表页首屏加载 ≤ 2 秒 |
| 数据安全 | AI 诊断数据仅内部可见，不暴露给外部用户 |
| 兼容性 | 支持 Chrome、Edge 等主流浏览器 |

| 阶段 | 内容 | 优先级 | 预估工期 |

| P0 | 接入"诊断 AI 智能体"，新增待办自动诊断 | 高 | 2 周 |

| P2 | 存量待办批量 AI 诊断 | 中 | 1 周 |
| P2 | 批量转派、批量删除功能 | 中 | 1 周 |
| P3 | 数据埋点与效果评估看板 | 低 | 1.5 周 |
